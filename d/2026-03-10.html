Anthropic 今天发布了 Claude Code 的新功能 Code Review，针对 GitHub 上的每个 Pull Request（代码合并请求）自动派出一组 AI Agent 进行深度审查，目前面向 Team 和 Enterprise 计划用户开放研究预览。

（注意个人用户还用不了）

这个功能的背景：过去一年，Anthropic 内部工程师的代码产出增长了 200%，代码审查成了瓶颈。他们发现客户也面临同样的问题，开发者疲于应付，很多 PR 只是被快速扫一眼，而非认真审读。

Code Review 的工作方式是：当 PR 提交后，系统自动派出多个 Agent 并行查找 bug，交叉验证以过滤误报，再按严重程度排序。

最终在 PR 上生成一条汇总评论，外加逐行的具体标注。大型复杂的 PR 会分配更多 Agent 做更深的审查，小改动则轻量处理，平均审查时间约 20 分钟。

Anthropic 自己已经内部使用了几个月。使用前，只有 16% 的 PR 能收到实质性审查意见；使用后，这个比例升到了 54%。

在超过 1000 行改动的大 PR 中，84% 会被发现问题，平均每个 PR 找出 7.5 个问题。工程师对结果的认可度很高，不到 1% 的发现被标记为误报。

他们举了个例子：一个看起来很常规的单行改动，实际上会导致生产环境的身份认证功能失效。Code Review 把它标记为严重问题，提交代码的工程师事后承认自己不会注意到这个问题。

不过这个功能不便宜。它按 token 用量计费，每次审查平均花费 15 到 25 美元，随 PR 规模浮动。管理员可以设置月度预算上限、选择启用的仓库，也有分析看板追踪使用情况。

值得注意的是，Code Review 不会自动批准 PR，最终是否合并仍由人决定。它的定位是补上人工审查的盲区，而非取代人类审查者。

Anthropic 此前已有开源的 Claude Code GitHub Action 做轻量审查，这次的 Code Review 是更重量级、也更贵的选项。

为什么世界是一个巨大的草台班子？

你有没有发现，组织里坐在决策位置上的人，往往不是一线出身。他们可能是财务、投资或管理背景，对具体业务逻辑知之甚少。

那些对外官宣的战略规划、投入方向，实则是基层团队写好稿子，高层照念。

即便一线出身的负责人，在管辖范围扩大后，也难以对所有领域保持精通。所以他们对外看似懂行的表达，同样离不开专业团队支撑。

于是便形成一个看似矛盾却极为普遍的现象：外行指导内行。

一线从业者，深耕专业领域，精通技术、产品、运营落地，往往是组织创新的执行力量。

顶层管理者，核心能力聚焦资源层面，深谙投资者关系、商业逻辑拆解、组织治理。他们无需精通一线业务，只要掌握资源整合的核心，便能调动专业力量为己所用。

这两种角色能力本应互补，但在现实中常常相互错位。

之前OpenAI的宫斗戏就是一个经典案例。

奥特曼是投资人出身，他的核心能力在于整合资源：向马斯克等投资方争取资金，聚拢伊利亚等核心技术人才，推动团队完成ChatGPT研发。而ChatGPT的核心技术突破，实则由伊利亚带领的研发团队实现。

ChatGPT成功后，奥特曼推动OpenAI商业化转型，却与坚持非营利初衷的伊利亚产生矛盾，最终被董事会罢免。

奥特曼的困惑，反映出资源思维与专业思维的差异：资源视角下，商业化是组织持续发展的必要条件。而专业视角下，坚守初心有时候比商业利益更重要。

专业能力是根基，资源运作是翅膀，二者缺一不可。问题在于，当根基和翅膀朝不同方向使劲时，谁来平衡？

这个问题没有标准答案，我们只知道最终结果是伊利亚走了，奥特曼回来了。

组织的通行做法是让资源思维坐在驾驶位，专业思维坐在副驾驶。因为最终金主信任的往往是资源决策者，不是专业负责人。哪怕这个人对专业一窍不通、恣意妄为，这就是“草台班子”的真相。

然而真正的问题不在谁握方向盘，而是两种价值尺度能否被组织同时容纳。资源尺度看重投入产出，专业尺度看重突破本身。一个组织如果只有前者，会失去未来。如果只有后者，会活不过今天。

这需要资源负责人有判断专业价值的眼光，也需要专业负责人有用资源语言翻译专业价值的能力。能同时做到的组织，才能让做成事的人留下来。

类似的草台戏码未来必然还会反复上演，直到有人想明白：让两种价值尺度共存不是一道选择题，是一道必答题。
